# HTTP 历史清理与容量记录

修订日期：2026-10-14。状态：开发分支实现与局部实测，未合并或发布。完整 M5 容量及 24 小时验收仍待完成。

## 修正的问题

此前默认每小时执行一次保留任务，每次至多清理 10000 条 HTTP 任务。100 个观测点各检查 3 个服务、间隔 60 秒时，理论上每小时产生 18000 条、每天 432000 条；当数据开始过期，清理上限低于新增速度，物理积压会持续增长。这里是调度频率推导，不是实测一天的 Server 数据增长。

现在每个事务至多删除 1000 条任务和 1000 条已闭合计划区间。启动时原保留事务仍构建主机/延迟汇总，并执行一批 HTTP 清理；工作线程启动后等待 100 ms，再独立追赶 HTTP 积压。周期保留完成后同样留出 100 ms。达到任一批次上限就保守认为可能还有工作，在释放写锁后等待 100 ms，再继续一批。恰好达到上限可能多执行一次空批；没有积压则等待原保留间隔，默认一小时。

清理失败记录错误并在 5 秒后重试，不等下一小时；关闭时取消事务/计时器。原主机汇总时钟继续独立运行，HTTP 积压不会令其等待整个追赶过程。配置和协议不新增字段；清理日志仅含已提交数量、保留边界及是否需要后续批次，不是总积压数量。

## 数据契约与升级

HTTP 保留仍为 31 天，截止时间向下取整到 UTC 秒。删除严格早于边界的任务，以及结束时间小于等于边界的已闭合区间；跨越边界和未闭合区间保留。任务时间的无小数、零小数和纳秒形式正确保留恰好边界的样本。统计/诊断继续按保留水位裁剪，不把已删除历史算成缺测或健康。

每批在同一事务内更新单调水位、删除两类数据；任一步失败整体回滚，返回零已提交工作。后续清理使用已公布水位，即使时钟回拨也继续处理已隐藏的过期行，不降低水位。分批并发由 SQLite 写事务串行化，不重复计算删除量。`ApplyRetention` 本身仍是原子事务；额外 HTTP 批次是独立提交，后续失败不会撤销前面成功的批次。

迁移 038 仅给 `http_schedule_epochs(end_ns)` 添加非 NULL 部分索引，使闭合区间按结束时间取批无需扫描所有开放区间。不改旧迁移、不回填或重写历史，不清理事件、通知尝试、证书永久去重或导入永久回放记录。升级前保留可恢复的完整备份；现有闭合区间的索引构建有启动写锁/磁盘成本，不能保证大库升级无停顿。

SQLite 删除释放可复用页，不承诺缩小数据库文件；本实现没有新增自动 VACUUM 或截断 WAL 的操作。

## 测量方法

使用临时磁盘 SQLite，WAL、synchronous=NORMAL、4 个连接。100 个合成节点、3 个服务、300 个开放区间；按服务/节点分散生成已过期任务，计划间隔 60 秒，保存合成任务和成功结果 JSON，另生成 10000 个闭合区间，以及精确边界数据。数据由 SQL 生成，不是实际运行 31 天的 Agent/调度记录。

后台单写入线程每 10 ms 尝试轮换节点写入一份合成资源上报，上一写入阻塞时 Go ticker 丢弃期间 tick，未产生完整的 100 次/秒队列；只统计实际尝试/成功的写入。清理调用真实 `PruneHTTPHistory`，每个满批等待 100 ms；统计总时长、最长批次、同次运行上报写入等待和物理文件大小。准备数据库不计入清理时间，但批间等待计入；每个规模使用独立新库，单次样本，没有独立冷启动/预热控制、温度测量或资源隔离。

环境：Windows 10.0.19045 amd64、i5-13490F、16 逻辑 CPU、操作系统报告 RAM 34138931200 字节、KIOXIA EXCERIA PLUS G3 NVMe（约 2 TB）、Go 1.26.5、CGO_ENABLED=0。数据库在本机临时盘。未限制到规划的 2 vCPU/2 GiB；无真实浏览器负载或 Gateway/Agent 网络，未测 Server CPU/RSS。

初始追赶候选沿用每事务 10000 行，随后仅缩小至 1000 行，保留相同追赶间隔、部分索引、数据和并发写入方式。候选不是已发布版本，也不是旧版“每小时一批”的完整运行实测。原候选清理源文件 SHA256 与精确样本见 [原始摘要](evidence/http-retention-capacity-2026-10-14.json)。随机 ID 和磁盘缓存可能带来差异，不应把单次比值当成稳定加速倍数。

## 验证与复现

正确性覆盖：任务/区间边界、失败后水位和两表整体回滚、取消、并发批次、时钟回拨、开放/跨界区间、每批后资源写入、索引查询计划、037→038 保留原数据、一致性备份恢复，以及清理后原导入请求仍能回放。真实工作线程连接临时数据库，在小时计时器之前清完 2500 条过期任务并保留新任务；另验证批间等待、失败退避重试、原汇总时钟和退出。

```powershell
$env:CGO_ENABLED = '0'
go test ./internal/store ./cmd/server -run 'HTTPRetention|RetentionWorker' -count=1
go test ./internal/store -run '^$' -bench '^BenchmarkHTTPRetentionCatchup$' -benchtime=1x -count=1 -timeout=10m
```

基准会生成约 620 MB 的最大数据集，包含准备工作的本次完整命令约 151 秒；默认全仓测试不执行基准。复现 10000 行候选应仅在隔离开发副本将内部批次常量改为 10000，使用相同基准，不对生产库运行。

这批解决 HTTP 清理吞吐上限与写锁占用；尚未完成原始主机/延迟汇总的大库成本、10000 个永久回放记录的真实存储、全系统 100 节点/5 浏览器的 2 vCPU/2 GiB 基准、30 天/一年历史查询、24 小时实时时长和故障注入。以上继续沿后续开发文档验收。
