## 部署和启用

1. 单独保存原始 `MYPROBE_ENCRYPTION_KEY`。它解密数据库中的通知凭据，与
   `.mpb` 备份口令用途不同。
2. 通过独立秘密文件托管至少 12 个字符的备份口令，设置
   `MYPROBE_BACKUP_PASSPHRASE_FILE` 为服务端可读的文件路径，再重启 Server。
   只移除文件末尾的一组 LF/CRLF；口令中的其他空格保留。文件上限 4096 字节，
   必须为普通文件，不接受符号链接。页面、数据库和任务元数据均不保存该口令。
   文件内容每次执行重新读取；更换口令后，旧文件仍须使用旧口令恢复。
3. 为服务账户准备专用、本地、支持硬链接和原子重命名的目录。使用服务端绝对路径，
   不与其他数据库共享。不与不可信账户共享写入权限。Unix 新目录模式 0700，
   新文件 0600；Windows 必须由部署者为服务账户设置相应 ACL。
4. Docker 需要分别挂载备份目录和秘密文件，并将环境变量路径设置为**容器内路径**。
   只声明环境变量不会自动挂载文件。`.mpb`、原始备份口令、应用密钥须分别纳入
   可恢复的保存方案；备份目录中的归属文件不是解密材料。
5. 在通知中心配置并启用至少一个失败提醒渠道，再保存目录、每日时间、IANA 时区、
   保留份数和渠道。最多 20 个渠道、1—1000 份成功备份。保存启用设置时实际检查
   口令、渠道解密、目录写入/同步/硬链接和两处磁盘空间。不满足时不保存新设置。
   停用不依赖已经删除或停用的渠道；页面可移除失效选择。

不得把正在写入的 SQLite 主文件直接复制作为完整备份。主文件之外的 WAL 中也
可能存在已提交数据。完整迁移运行记录、认证、通知和永久回放证据须使用完整备份，
配置 JSON 不能替代完整数据库。

Docker 可使用单独的 `compose.backups.yaml`（不要把口令文件提交到版本库）：

```yaml
services:
  myprobe:
    environment:
      MYPROBE_BACKUP_PASSPHRASE_FILE: /run/secrets/myprobe_backup_passphrase
    secrets:
      - myprobe_backup_passphrase
    volumes:
      - type: bind
        source: ./backup-archives
        target: /backups
        bind:
          create_host_path: false
secrets:
  myprobe_backup_passphrase:
    file: ./private/backup-passphrase
```

由部署者事先创建目录与秘密文件，并授予容器服务账户必要的读/写权限；随后
`docker compose -f compose.yaml -f compose.backups.yaml up -d`，页面目录填 `/backups`。
不改变现有 `myprobe-data` 挂载。systemd 的 `DynamicUser` 和沙箱也需要能够读取秘密
文件；默认可写状态目录内的 `/var/lib/myprobe/backups` 可作为本地输出，外部输出目录
另行授予服务权限。不要为了启用备份移除整个服务沙箱。

## 每日调度与重启

- 每 15 秒检查一次；当前本地时刻达到设置的 `HH:MM` 后领取当前日期。
  当天启动晚于计划时间会补跑一次，不重放往日积压。
- 领取任务和更新本地日期上限在同一 SQLite 事务内。日期上限不随历史清理删除。
  时钟回拨、夏令时重复小时、当天修改时区/时间、重启均不会重领已领取日期。
  夏令时不存在的分钟在下一个观察到的符合时间的分钟执行。
  时区修改后，如果新时区日期不大于已领取日期，则等待更大的日期。
- 每日失败仍占用当天标记，避免故障时每次检查都重试并发送提醒。修复配置后，
  管理员可“立即执行一次”；手动任务不改变每日日期标记。
- Server 为这个数据库持有独立的进程生命周期工作锁；目录还持有独立的排他锁。
  其他实例不能接管仍存活的工作线程或目录。取得工作锁后，启动恢复将遗留的
  `running` 任务记为 `interrupted`，并在同一完成事务中创建失败提醒。
- 备份及恢复演练各限制 30 分钟，后台执行与浏览器连接无关。保存设置与执行互斥，
  有任务时返回 409，不在 HTTP 写超时内等待一个大型快照。

## 文件完成和保留边界

每次执行：空间/权限预检 → 一致快照 → 加密临时输出 → 文件同步 → 完整解密 →
明文 SHA-256 对比 → SQLite 完整性检查 → 不覆盖同名文件的硬链接发布 →
签名完成清单发布 → 保留清理 → 数据库结果和失败提醒事务。

成功清单记录开始/完成时间、大小、密文 SHA-256、归属及验证状态。初始状态是
`archive_verified=true, recovery_verified=false`。工作目录独立随机命名、权限受限；
在写入明文前同步签名清理授权。进程被杀而无法执行 defer 时，下次取得同一目录
归属锁后，验证授权，再通过目录句柄删除固定的 SQLite 临时文件和空目录。
不递归删除，不清理没有有效授权的目录，不跟随符号链接。

保留清理仅选择当前数据库/目录归属、签名有效、普通文件、大小及密文校验和均未变
的成功清单，先保留刚完成的归档，其余按记录完成时间保留最新份数，避免时钟回拨
使本次成功文件立即被当作旧文件删除。其他文件、修改/截断文件、无清单密文、
符号链接及未知部分文件均不自动删除。中断留下的加密部分文件或未完成清单的密文
可由管理员核对后处理；本功能不通过宽泛通配符猜测归属。

加密输出和完成清单分别原子发布，签名清单是成功库存依据。清单发布前中断不会
成为成功库存；完成记录持久化前被杀，任务仍会标记中断。成功文件和历史任务记录
不是同一件事；清理后仍保留任务历史。清理失败时保留新备份的元数据，但任务为
`failed / backup_cleanup_failed`，并触发提醒。

预检在源数据库磁盘和输出磁盘均保守预留 `3 × allocated_bytes + 64 MiB`；同盘
覆盖快照、验证明文和密文的合计。演练还按备份大小检查源目录的
`2 × archive_bytes + 64 MiB`。这是保守门槛，不保证生成期间没有其他进程耗尽空间。
写入、同步、发布任一步失败都不替换上一份成功文件。

这些验证覆盖正常退出与真实进程强制终止。文件同步和进程中断测试不等价于主机
断电、文件系统损坏或磁盘硬件故障的耐久保证；本地硬链接不可用则拒绝启用，不降级
为可能覆盖的普通复制。S3 和跨机器存储尚未接入。

## 失败提醒契约

迁移 039 增加独立 `system_notifications`，无需虚构节点或告警事件。
备份失败状态和每个所选渠道的一条提醒在同一事务中提交；事务失败不会只写入
任务完成。渠道名称/Provider/配置版本作为历史快照，正文只包含安全错误分类，
不含数据库路径、目录、秘密文件名、口令或通知凭据。

实际通知使用原有 Provider Sender、渠道加密、错误分类、退避及持久共享等待。
最多五次尝试，每次发送限 20 秒；频道 `Retry-After` 影响普通事件、聚合与系统提醒。
领取后在写事务中再次验证当前渠道启用、Provider、配置版本和等待状态，授权发送后
才进行网络 I/O。等待导致的未发送预留退回重试预算；删除、停用或替换渠道会取消
尚未授权的提醒。

授权后进程中断、租约过期或明确分类为不确定结果时，保留 `unknown`，不自动重发。
`inflight` 仅表示持有租约，`delivered` 表示 Provider 已确认，不保证用户已阅读。
结果不会修改“通知测试”的状态；迟到旧版本结果不能延长新版本配置的等待。
没有可用应用密钥时会留下失败证据，不能声称已发送提醒。独立系统通知消费者不
依赖主机故障评估首次成功，技术故障与备份提醒的身份和状态分别保留。

页面显示最近 50 条任务和提醒，按 10 条分页；渠道选择按 25 条分页、名称搜索，
跨页保留选择。已完成/失败的任务最多保留最近 1000 条；仍有 pending/inflight
提醒的旧任务暂不删除。系统健康队列以只读同一事务分别统计故障、聚合和系统提醒，
不领取任务、不解密正文、不到期租约。

## 隔离恢复演练的含义

“执行隔离恢复演练”会验证当前目录归属和密文哈希，使用当前独立秘密文件解密到
私有临时目录，再通过正常 Store 打开隔离数据库：检查 SQLite、所有外键、用户/
节点/原始样本/渠道计数，读取站点及版本化配置，并以当前应用密钥解密每个恢复
渠道。只有全部成功并同步记录后才写入签名的 `recovery_verified=true`、时间和
计数证据，再同步任务历史。错误口令、错误应用密钥、截断文件或其他失败不能获得
该标记。已被保留策略清理的文件不能再演练，须从仍存在的备份选择。

演练不运行恢复数据库中的调度、通知、Agent 或会话，不替换当前库。标记具体含义为
**该文件曾通过隔离数据库读取及通知凭据解密**，不是当前生产故障切换、Agent 重连、
外部服务或客户端恢复证明。换口令/应用密钥后仍需保存旧材料；既有历史验证时间
不保证新材料能打开旧文件。上传暂存并重启的实际切换仍使用原手动恢复流程。
演练中断不会在重启后自动续跑或获得标记，可在文件仍在时重新发起。

## 私有 API

全部先设置 `private, no-store` 再校验管理员身份；修改操作还校验现有 CSRF Token。
不提供备份目录公网浏览、秘密上传或公开文件下载。

| 方法 / 相对 `/api/v1/admin/maintenance/backup-schedule` | 结果 |
| --- | --- |
| GET 空路径 | config、口令可读布尔值、运行状态、最近 50 条任务/提醒 |
| PUT 空路径 | 严格 JSON 配置；启用预检成功后保存，200 |
| POST `/run` | 已启用时接受后台手动备份，202；停用/互斥冲突 409 |
| POST `/runs/:id/verify` | 现存完成记录接受后台隔离演练，202；没有备份元数据/非法记录 400，互斥冲突 409；已清理/改变的文件在后台结果中报告 |

只返回安全错误分类。GET 的目录是管理员主动设置的私有部署配置；口令文件路径、
应用密钥、渠道密文和内部租约不返回。保存、执行和演练均留审计；审计不包含目录
或秘密材料。页面在 401/403 时清除设置/记录并退出，503 保留上次结果并禁止修改；
轮询不覆盖未保存编辑。维护入口支持刷新和浏览器返回。
