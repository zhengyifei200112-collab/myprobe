# 当前服务状态与多观测点摘要

需求基线：MyProbe后续开发文档.md 第 6.2、6.4、18.5 节。适用于服务开发分支，待评审发布；不表示全部 SVC-03 或 M3 已完成。

## 用户行为与汇总规则

HTTP 服务列表同时显示配置开关与状态快照。点击“服务状态”查看当前配置的全部观测点、成功/失败/未知数量、受限原因、计划及完成时间；“刷新当前状态”重新读取，“查看服务告警与事件”进入已有事件和通知管理。

固定策略 any_required_observer_failure，当前所有已分配观测点均视为必选，不做投票、平均或隐藏缺测：

| 新鲜有效结果 | 摘要 | 当前有效观测覆盖 |
| --- | --- | --- |
| 2 点成功 | healthy / 服务正常 | 2/2 = 1 |
| 1 点失败、1 点成功 | degraded / 服务降级 | 2/2 = 1 |
| 1 点失败、1 点未知 | degraded / 服务降级 | 1/2 = 0.5 |
| 1 点成功、1 点未知 | unknown / 服务状态未知 | 1/2 = 0.5 |
| 2 点未知 | unknown / 服务状态未知 | 0/2 = 0 |
| 没有已分配观测点 | unknown / 服务状态未知 | null，无分母 |

当前覆盖 = 当前成功或失败的观测点数 / 已分配观测点数，取值 0–1。它不是时间范围内的计划任务覆盖、历史有效检测成功率或 SLA。两点都失败也能有当前覆盖 1，因此覆盖不能替代健康状态。

摘要不需要启用告警或有效通知通道，读取也不会创建事件或发送通知。检查失败时，摘要可先降级，事件仍等待触发窗口；新鲜检查成功时，摘要可正常，原事件仍等待恢复窗口。知悉、静默和节点维护仅影响现有事件处理/投递，不能把失败改成成功。服务停用或执行关闭为未知，不把已留存成功当作现在正常。

## 共用观测契约

内部 servicehealth.Evaluate 同时用于私有摘要和原服务告警评估。保留服务事件文档的当前版本/计划槽、在线窗口、能力协商、缺测与新鲜度语义：

- 读取当前服务版本和当前关联，按每个观测点选择不晚于查询时刻的最新计划任务。较新待结果任务遮住旧成功或失败，未来任务不遮住当前任务。
- 主机上报在线、持久能力元数据和当前 Gateway 会话协商均须成立。旧协议替换会话即使留下 HTTP 能力元数据，也不能使用旧成功证明健康。
- 计划和完成时间均不超过 max(60 秒, 3 × 服务间隔)；主机上报不超过 max(20 秒, 3 × 上报间隔)，超前超过 30 秒也无效。
- 待结果在任务过期加 60 秒回报宽限内为 pending，超过后为 missing_result。两者都未知；缺测原因不是目标故障。
- unobserved 的 policy_denied、unsupported、busy 等使用受限分类。实际合法 failure 为失败，success 为成功；未知或非法分类不会原样回显。
- 服务定义或关联修改后，旧版本结果不能进入摘要。服务遗留零节点时仍返回服务本身，不能因空集合变成正常。

节点维护当前只抑制通知，历史统计仍 maintenance_excluded=false；本批不修改维护统计分母。详情说明已清理/未执行的证据边界，不以当前快照推断历史故障时长。

## 受保护 API

GET /api/v1/admin/service-monitors 保留原游标页、ID、名称、版本、配置开关等字段，新增每项 health。默认 50、上限 100 个服务。GET /api/v1/admin/service-monitors/:serviceID/health 返回安全服务摘要、health、至多 100 个当前观测点及实际 execution_enabled；此接口不接受查询参数。

两个接口要求管理员会话并使用 no-store。原公开节点和 Agent 合约不新增字段。service 定义不包含 spec，观测点不包含公网/内网地址、capabilities、last_seen 原始字段、URL、请求或断言正文、令牌和通知密文。只返回安全别名、身份、受限原因、任务时间及有效结果的状态码/耗时。未知状态不把旧状态码和耗时展示为当前成功证据。

health 字段：

| 字段 | 契约 |
| --- | --- |
| state | healthy、degraded 或 unknown |
| policy | any_required_observer_failure |
| required_observers | 当前关联节点数量，0–100 |
| success / failure / unknown | 整数，三者之和等于 required_observers |
| current_coverage | 0–1；无观测点为 null |
| as_of | 服务端本次评估时间，UTC RFC3339 |
| valid_until | 已知观测中最早的新鲜度截止；未知且无已知观测时省略 |

观测点 status 为 success/failure/unknown；未知 reason 区分 service_disabled、execution_disabled、agent_offline、unsupported、agent_unavailable、not_observed、pending、missing_result、stale_result、unobserved 或 invalid_result。error_class 只包含预定义实际失败/未观测分类。任务时间是最近证据时间，不代表整个区间都正常。

## 读取、容量边界与页面过期

每个有界服务页通过一条 SQLite 查询读取服务定义、关联、主机上报/能力及当前版本最新任务，利用既有 034 的服务/节点/版本/规范化计划时间索引，不扫描私有任务 spec。空关联通过 LEFT JOIN 保留。最多 100 个服务、每服务 100 个观测点，超过上限或数据无法解析时封闭失败，不返回部分正常结果。请求查询限时 5 秒。

Gateway 对所选去重节点在一个读锁下捕获当前会话和执行开关。数据库与活动连接是两个读取来源，不能声称是跨 SQL/网络的原子历史快照；它们反映本次查询时的状态，后续任务、断连或配置变化仍须重新读取。列表页若在选择和快照间删除服务，省略该项并保持原游标；其余字段使用快照内当前定义，不拼接旧版本结果。

valid_until 取已知观测的计划、完成、在线证据截止中的最早值。浏览器根据服务端 as_of 到截止的间隔和发起请求时的本地单调时钟处理，有效显示最多 30 秒。请求耗时计入该期限，不依赖客户端与服务端时钟同步。过期时列表和详情撤去正常/降级颜色及当前计数，显示“状态快照已过期”；读取失败也撤去旧正常状态，允许刷新恢复。页面不自动持续查询，不把缓存称为实时数据。

当前摘要复用既有表和 034 索引，本摘要模块不新增迁移、不改变 Agent 包络或通知正文。后续独立证书提醒使用 035，预警不改变本摘要；详见 [证书提醒契约](CERTIFICATE_REMINDERS.md)。页面不是服务/观测点/时间范围诊断深链；维护排除、更多竞态与完整保留/容量验收继续保留。

## 验证与后续

定向命令：go test ./internal/servicehealth ./internal/store ./internal/alerts ./internal/httpapi ./internal/agentgateway -run '^Test(Current|HTTPHealth|ServiceHTTP|ServiceHealth|VersionedSocket)' -count=1。

覆盖混合失败/缺测、空分母、在线和新鲜度精确边界、未来时间、待回报/宽限、未知分类、不泄漏原因、规范化纳秒计划顺序、未来任务排除、当前版本/关联/零节点、认证/no-store 和公开字段隔离。实际 SQL 的 EXPLAIN QUERY PLAN 验证最新观测查询使用 034 的索引；它不是完整负载验收。实际 v2 → v1 → v2 连接替换验证持久能力不等于当前会话执行能力。API 验证摘要不要求或修改告警配置、不创建事件，维护通知窗口不修改检查状态；事件状态机及既有通知回归复用相同判定。

扩展 TestServiceIncidentThroughRealAgent：两个真实 Agent 一个显式允许私有测试目标，另一个本地策略拒绝，网站失败时得到失败加未知的降级；网站恢复后为成功加未知，保持整体未知；只重启第二 Agent 并开启本地允许策略后全部成功，整体正常；断开第二 Agent 后即时排除仍新鲜的旧成功。原事件故障/恢复及两条持久回执身份不变，策略拒绝的 Agent 不产生伪故障。

scripts/service-health-live-ui.cjs 使用实际服务端、Agent 和受保护 API，检查上述三种汇总、原因及当前覆盖、登录前无私有读取和 18 个明暗主题/宽度视图。正常阶段实际等待 21 秒验证快照过期，随后验证刷新和读错误恢复；读错误注入是浏览器拦截的 503，不宣称实际 Provider 或基础设施故障。既有事件登录/保存/历史入口和全部告警浏览器回归仍需运行。
