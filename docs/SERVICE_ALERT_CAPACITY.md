## 数据与环境

一个合成观测节点、1000 个停用的 HTTP 服务、1000 个合成 Webhook 通道，每个服务已有一份停用告警设置。仅将整批冷却参数从 300 改为 301 秒，不执行网络检查或外部通知。目录始终含完整 1000 服务和通道，浏览器单会话、单页面，非限速本机回环 API，临时 SQLite 数据库。

优化后环境：Windows 10.0.19045 x64、i5-13490F、16 逻辑 CPU、34138931200 字节物理内存，Node v24.19.0、Edge 155.0.4283.45、Go 1.26.5、CGO_ENABLED=0。数据库位于本机临时目录；没有记录磁盘型号/性能，不视为规划中的 2 vCPU/2 GiB 环境。旧基线在同一开发机、`b83a8ef9a495595fd80ac9d11ed9a6573da191fd` 的原界面测量，当时没有采集完整版本与硬件元数据。

计时从上传 JSON 开始，到映射区域可用，包含文件处理和目录读取，不是单独的 Vue 渲染时间。每行是一次顺序样本，50/1000 项承接此前页面与缓存，未做独立冷启动、预热阶段、CPU 隔离或长时间采样。

原界面为每个来源重复渲染全部目标选项，完整上限按结构会生成约 200 万个 option。没有实际运行原界面的 1000 项样本，不声称测得其耗时、崩溃或 OOM。新界面每类只渲染 25 个来源，选择器也只渲染 25 个目标；表内元素仅计算迁移区域，不含弹窗和页面其他部分。6 个 option 来自两个三项来源过滤器。原始目录仍完整保存在内存，服务端不会截断。

JS 堆由 Chromium `performance.memory` 读取，包含整页，未强制 GC；不是浏览器/Server RSS 或稳定内存上限。单次样本只能证明本数据上消除了重复选项开销，不能推出其他硬件的延迟承诺。

## 完整请求与恢复

五次连续的完整 1000 项预览分别为 77.3、68.4、67.3、67.8、67.6 ms，中位数 67.8 ms。一次完整应用为 127.8 ms。预览计时包含本机请求与完整 JSON 读取；应用计时在浏览器拦截器中测量真实请求及完整结果读取，未包含点击/缓存操作。样本数不足以作为长期 p95 指标。

提交成功后故意隐藏响应并返回 503，刷新页面，再以原 request_id 和 preview_digest 确认。待确认缓存为 480302 字节，含完整 1000 项原请求，省去重复的预览行。服务端返回原结果，浏览器清除缓存；Go 在脚本结束后核对全部 1000 个设置的冷却值为 301、告警修订恰为 2、服务修订仍为 1，两类提醒保持关闭，证明屏幕外行也更新且回放没有再次写入。

浏览器还验证：末项搜索与明确选择、完整映射文件、部分清空后保留其余 999 项、未知字段/来源/目标和重复服务目标整份拒绝且原选择保留、旧预览失效、完整预览的 25 项分页、目标分页/搜索、Escape 关闭和焦点返回，以及浅色/深色的 360/768/1440 px 共 6 视图。独立迁移回归保留旧无版本完整预览缓存的恢复、跨 Provider、过期预览、损坏/不可用存储检查。

## 复现

先按项目要求构建 `web` 并保留 `internal/webui/dist`。Windows 下准备可被 Node 加载的 Playwright 和 Edge：

```powershell
$env:CGO_ENABLED = '0'
$env:MYPROBE_TEST_SERVICE_CAPACITY = '1'
$env:PLAYWRIGHT_MODULE = '<Playwright 模块绝对路径>'
go test ./internal/httpapi -run '^TestLiveServiceAlertCapacityBrowser$' -v -count=1
```

测试自行创建隔离数据库和本地服务器，输出临时目录中的 `measurements.json` 与截图，结束后关闭服务器。默认全仓测试跳过此需要浏览器的显式用例。`MYPROBE_CAPACITY_BASELINE=1` 只运行 10/50 项载入测量；只有搭配原界面才是原基线，不可在新界面运行后将结果标为旧界面。

仓库内 [原始测量摘要](evidence/service-alert-capacity-2026-10-13.json) 不包含机器路径、随机通道 ID、会话或数据库内容。
