# 报告回执、入库与渲染收敛验收

原联合负载只验证“已存报告来自生成器且不重复”。采集可以被最新缓存跳过，
WebSocket 写成功也不等于 Server 入库，因此不能用采集数减入库数声明零丢包。
本夹具增加可选择的测试观察层，继续使用正式 `Client.Run`、正式 Server 与真实任务。

## 观测范围

设置 `MYPROBE_TEST_LOAD_RECONCILE=1` 后，Agent 连接测试专用 loopback 转发端。
转发端逐封套保留版本、sequence、原 payload、配置 nonce 和任务内容，记录报告
进入观察层、向 Server 写入和 Server 的匹配 ACK；HTTP fallback 记录原 JSON
及真实 HTTP ACK。认证 token 仅用于内存中的合成节点映射，不写入报告。

此层重新编码 WebSocket 封套并增加一次网络跳转，位于 Server 资源限制组外，
不能把其额外开销与原直连性能数据混为同一条件。它证明观察层看到的发送与回执，
不证明每次采集都尝试发送。额外核对每个正式 Client 实际生成的全局 sequence
1…N（包含 hello/报告/任务结果/heartbeat/配置回执），要求每个都进入观察层；
生成后尚未到达观察层的封套会单独计数并使测试失败，不让代理前的缺帧被漏掉。
这些缺帧不能在没有证据时直接归类成报告，原始失败原因仍须继续分析。

正式 Server 停止后，通过 node/captured_at 对全部实际报告逐条核对 hash。
Server 补入的观测 IP 在原指标比较时单独去掉，保留原数据库内容不修改。
以下情况失败：已 ACK 但没有入库、未知来源、内容变化、重复存储、没有解释的未入库。
已存但没有 ACK 单独计数，不能误称数据丢失。

未收到 ACK 且未存储的报告，只有观察到转发失败/连接中断并且报告距中断不超过
10 秒才分类为传输中断；后来很久才关闭连接不能替早先的静默丢弃作解释。
测试覆盖这些反例，以及错误节点/序号 ACK 不能确认另一个报告、重复 ACK
不能刷新首次确认时间。统计只输出聚合计数和延迟，不输出节点 ID、地址或封套。

## 页面收敛检查

测量及通知排空后先停止普通 Agent 循环，再通过真实 Agent HTTP 发送每个节点
带特定 CPU 值的最终报告；保留累计计数和源 hash。五个真实页面继续运行，
测试仅读取现有 DOM 中每个合成节点 CPU 进度条的 aria-valuenow，等待最多
20 秒与全部最终报告一致。不会刷新页面、替换 Vue 状态或用 API 数据冒充 DOM。

该阶段验证停止普通更新后的最终收敛，不等于持续运行期间每一帧都显示过，
也不等于浏览器渲染延迟分位数。普通测量、恢复排空与最终标记分别解释。
如果当前 Hub 的非阻塞订阅丢弃使页面未收敛，断言必须失败，不能靠强制重载通过。
