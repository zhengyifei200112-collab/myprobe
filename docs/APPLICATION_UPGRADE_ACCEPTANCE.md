## 输入与隔离

输入为已闭合且校验摘要的526,508,032 B一致备份：001—013迁移、2节点、
120302原始指标。真实数据库、匹配运行配置/应用密钥及登录信息始终留在远端私密
存储；没有下载到开发机或提交到Git。新Server使用Go1.26.5、CGO关闭、trimpath
交叉编译，源码归档与实际可执行文件摘要分别核对。

旧Server及Agent直接复制实际容器内应用进程的可执行文件，再核对摘要。容器PID1
是init时，不能把init文件当应用。实际部署Agent镜像标签虽为v0.2.0，其文件摘要与
公开发行v0.2.0资产不同；本次记录实际文件身份，发行资产另有兼容用例，不能互认。

所有应用只读原备份后向全新独占副本写入，监听私有网络命名空间的loopback。
内核接口查询要求仅有lo，网络命名空间必须不同于宿主；没有公网路由，真实通知
Provider及OAuth无法发送/授权。systemd运行时实读CPU25%、内存1GiB、swap0、
ProtectSystem=strict及独占可写目录，非全局设置。生产容器的镜像、启动时间保持
不变，Server仍healthy、Agent仍运行，没有切换公开流量。

## 运维复现与发布前仍须完成的事

1. 对准备升级的真实版本建立新一致备份，核对闭合状态、完整性、外键及摘要；
   安全保管匹配应用密钥、配置和实际旧应用身份。仅有备份文件不足以证明可恢复。
2. 在新私密目录/私网命名空间中准备独占副本。为新应用迁移和旧应用启动分别安排
   预算；先确认CPU/内存/I/O上限实际生效，再运行。sysfs挂载视图不能替代内核
   网络接口与命名空间身份检查。
3. 按上表依次核对真实启动、原认证、实际旧Agent、加密导出/流式上传、202暂存、
   停止/重启应用、节点/报告摘要/凭据和恢复前数据库保留。只有已执行的断言才能
   计为通过；观察超时、失败和输出目录碰撞都保留，不自动覆盖或续跑成成功。
4. 回退时使用独立的升级前数据库及匹配旧应用/配置。**不要让旧二进制打开已迁移
   数据库，也不要删除迁移记录伪造降级。** 明确备份快照之后的数据缺口；本演练
   中导出后合成标记被移除正是在核对该恢复点语义。
5. 真实部署前重新备份并由所有者批准切换，记录实际版本、恢复点和停机预算。
   本演练没有批准主线合并或发布。

本结果不扩展为跨机大库、公开生产切换、真实GitHub授权/Telegram发送或新整合源
容量/24小时。32MiB原生异机Store恢复见[异机归档](BACKUP_PORTABILITY.md)；
当前Oracle长测保持原轮次与原源码归属。加密归档、口令、私密配置、进程日志和
包含真实记录的所有数据库继续留在受控存储，筛选JSON只发布汇总检查和摘要。
