# 单节点实时发布与联合负载复测

联合运行基线在 100 节点、真实 15 秒报告、每节点三个 60 秒目标、五个渲染页面和
实际 2 CPU 配额/2 GiB Server 限制下，测得概览 API p95 730.06 ms，超过初始
500 ms 目标。基线只含本轮历史和 90 秒测量，不能据此宣称稠密历史或 24 小时通过。
完整基线见 [联合负载说明](JOINT_RUNTIME_LOAD.md)。

## 改动

Gateway 每次报告/延迟更新原来调用 `ListPublicNodes`，组装全部可见节点的报告、
metadata、延迟和流量，再选取一个节点发布。节点数量与更新数量一起增加时，
重复读取放大；不会因为 WebSocket 只发送一条事件而减少这些查询。

新增内部 Store 单节点查询，使用参数绑定和节点主键筛选；metadata 也按同一节点
主键查询。列表与点查询共享公开对象的解码、脱敏、在线/陈旧、商业状态、延迟
和流量组装。Gateway 发布这一个对象；公共全量概览/初始 snapshot 保持完整列表。

隐藏、不存在和空 ID 返回 not found，发布端沿用不发送的行为。不读取其他节点来
组装本次更新；与公开列表仍共用同一投影，不使用管理员原始节点 DTO。没有迁移、
配置、新字段、协议版本或事件类型变化。已生成/在途帧仍不能被后来的隐藏操作撤回。

回退应用可恢复原全量读取路径；数据库和协议不改变。

## 验证

点查询与公开列表在相同时间下逐字段相等；真实报告、masked IP、Agent 元信息、
商业状态、目标延迟和累计流量均覆盖。隐藏/不存在/空/注入字符串不会返回节点；
公有对象不出现主机名、软件版本、capability 或完整 IP。人为破坏另一个节点的
数值列会使原全量扫描报错，而健康节点点查询仍成功，验证它没有扫描无关节点。
Hub 回归检查可见更新与原事件形状，以及隐藏/不存在节点不发事件。

Store/Gateway 整包和针对性测试已通过。用同一个联合夹具、资源限制、机器、报告
周期、目标数和五个浏览器进行 5/50/100 复测；仅扩展 provenance 哈希清单以记录
修改的 Store/Gateway 源码，不缩减工作负载。实际结果与准确提交 CI 须单独记录，
不能凭结构改动宣称容量已经达标。

后续保留稠密 30 天/一年同时查询、完整发送/ACK/入库对账、实际 24 小时和原始
完整 M1—M5 范围。当前阶段不能把单次短测试的累计 CPU 或采样 RSS 当成长期门槛。
