# 服务诊断与受保护通知入口

## 范围和语义

管理员可按服务、单个观测节点及 `[start,end)` 时间范围读取历史诊断。读取不会触发网络请求、修改服务配置或重新执行任务。通知入口只包含内部服务 ID、节点 ID 和 UTC 时间，不包含目标 URL、地址、断言、正文或凭据。管理员会话校验先于查询校验；返回 `Cache-Control: no-store`。历史节点仍存在但已取消分配时，允许查询其旧记录并标记“当前未分配”；已删除的服务或节点返回 404。

诊断行只列出已下发任务，不代表全部计划槽位。成功、失败、未执行有效检查、等待回报、到期未回报分别呈现。无结果任务在 `expires_at + 60s` 收件宽限结束后才标记缺测。成功和失败才是有效检查；能力不支持、本地策略拒绝、繁忙、取消等属于未执行有效检查，不能推断服务宕机。超时无法定位到具体阶段。

同一 SQLite 只读快照返回服务摘要、节点名称和当前分配状态、历史任务以及成熟槽位的原始统计。统计沿用 126 秒成熟等待、已知调度历史和保留边界；缺测含未执行有效检查、未下发或未回报，不与下发任务行数直接相减。维护调整沿用独立检测统计入口，本页明确展示原始诊断。当前健康度使用现有“服务状态”入口，历史成功不会作为当前健康状态。

只有实际接收的总耗时、状态码、完成时间和允许的失败类别可展示。当前 Agent 未提供 DNS/TCP/TLS 分段耗时、解析地址或逐跳状态，本页不生成这些数据。分类仅说明已记录的失败证据。存储中的结果身份、时间、类别和数值不符合约束时整页失败，不返回任意导入文字或部分绿色结果。

## API 和分页

`GET /api/v1/admin/service-monitors/:serviceID/diagnostics?node_id=…&start=…&end=…&limit=50&after=…`

- 时间使用 RFC3339Nano，范围至多 31 天，年份 1970–2100；必填项缺失、重复项、未知参数、非法游标返回 400。
- `limit` 为 1–100，默认 50。返回 `service`、`observer`、`statistics`、`observations`、`next_cursor`、`server_time`、`execution_enabled`。
- 任务按纳秒计划时刻、任务 ID 倒序，通过专用表达式索引和 keyset 游标读取至多 `limit+1` 行；游标绑定服务、节点和请求范围，跨上下文使用返回 400。
- 每页是新的快照；翻页期间新收到的结果、保留清理和配置变化可能改变数据。游标不保证历史内容被冻结。刷新会从第一页重新读取，页面展示各次读取的服务端时间。
- 返回经过限定的诊断 DTO，永远不返回 `task_json`、`spec_json`、任意错误文字或证书主体。证书证据及续期提醒仍通过现有受保护证书入口读取。

## 通知导航

新服务故障/恢复/重复提醒和证书提醒在入库时固定 `service_diagnostic_path`，同时保留原 `incident_path`。范围为通知时刻前 30 分钟至后 5 分钟，使用通知事件的来源节点；这是诊断上下文，不是精确故障持续时间。证书来源节点是固定提醒规则锚点，证书证据可能来自其他分配节点，须在证书页查看证据池。

路径 `/admin?service=…&observer=…&start=…&end=…` 支持密码登录、已登录访问、刷新和 GitHub 登录回跳。GitHub 回跳仅恢复同一浏览器会话中保存的一小时以内的规范入口；不接受任意跳转 URL。混合事件/聚合/服务入口、重复项和非法时间拒绝恢复。即使服务位于列表后续页，也独立读取指定诊断服务。查询成功后当前入口写回地址栏；查询失败清空旧结果。

诊断面板显示在列表之前并获得标题焦点，避免深链被大量服务卡片推到页面末尾。筛选输入保留 UTC 文本，列表与统计时间按浏览器本地时区显示。事件详情使用当前事件更新时间附近的范围；通知使用原入库时刻，二者可能不同。

Webhook 默认 JSON 包含新字段，自定义 Body 支持 `{{service.diagnostic.url}}`；Telegram、Discord、SMTP 提供独立诊断链接。使用经过验证的配置 origin；未配置时保留相对路径。原任务正文和幂等键保持不变，重试、重启和完整数据库恢复保留入库链接。JSON 导出不包含历史任务。新增迁移 036 仅添加索引，无 Agent 协议或公开 API 字段变更。

升级前沿用完整备份流程。迁移 036 需要为现有任务历史建立一次索引，索引构建和后续磁盘占用须纳入容量验收；不能将分页查询使用索引等同于已完成完整容量测试。

## 验收边界

覆盖严格查询和导航校验、登录前无私有读取、服务/节点删除及取消分配、纳秒边界和分页、保留和成熟边界、并发读一致性、不同失败及未执行类别、失败清空旧页面、渠道链接转义与正文预算、旧任务和完整恢复。浏览器在浅色/深色与 360/768/1440 像素检查登录、上下文恢复及布局；真实 Agent 验证入库故障/恢复结果可从通知进入对应历史。真实 GitHub OAuth、公网 Provider 客户端和长时间容量验收仍属后续发布门槛。
