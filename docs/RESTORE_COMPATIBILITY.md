# 备份与数据库迁移兼容性

恢复前，Server按自身内嵌的迁移名称核对数据库`schema_migrations`账本。
当前版本以及当前迁移集合内的旧版本可继续校验完整性，并在恢复后的正常启动中向前迁移。
上一正式版本的升级路径仍有独立回归，不能从实验分支的备份推断正式升级兼容性。

包含未知迁移记录的备份返回400：`database migration history is not supported by this server`。
此时不创建待恢复文件，当前节点、登录会话和数据库保持原状。若待恢复文件由其他路径放入，
启动激活前也会重新检查，拒绝时保留当前库与待恢复文件。
直接打开已有数据库时先进行只读迁移检查，再进入正常写入与迁移流程。

迁移名称是兼容性标识的一部分。两个实验分支即使使用相同编号，也可能采用不同布局；
遇到该错误，应保留原归档、必要密钥和生成版本，在匹配版本的隔离环境恢复，再按受支持路径迁移。
不要通过手工改写迁移账本把实验库伪装成兼容库。

检查读取已提交的WAL记录，限制不受信账本的返回文本和行数，并使用固定错误文本。
兼容性检查不替代完整恢复演练：仍需验证节点、策略、历史与必要凭据，并记录恢复点之后的数据缺口。
这项修改不新增迁移、不改写已有迁移，也不改变Agent协议或加密归档格式。
