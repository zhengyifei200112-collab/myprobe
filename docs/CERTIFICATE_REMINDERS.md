# 证书到期提醒：实现契约与验收

对应工作区后续开发文档第 6、17.3、18.5 节，属于 SVC-03 持续开发。
本批在服务集成开发分支实现；待 PR 评审、合并和发布，不代表 M3 或 M1–M5 完成。

## 用户流程

1. 启用服务端 HTTP 执行，选用支持 HTTP 的在线 Agent，并使其本地地址策略允许目标。
2. 管理中心 → HTTP 服务 → 服务告警与事件，选择通知通道，勾选“启用证书到期提醒（14／7／1 天）”。默认关闭，可独立于服务故障通知启用。
3. 新鲜检查中的已验证证书进入提醒档后，记录证书预警并使用原通知队列发送。点击通知可登录后回到原事件及尝试历史。
4. 在证书提醒记录中分别核对到期时间、SHA-256、档位、入队、发送授权及投递状态。页面同时显示浏览器时区与 UTC 原值。

证书预警不改变服务健康摘要或可用性分母。实际 TLS 无效或过期仍由 HTTP 检查分类为服务失败；提醒关闭、没有提醒记录或旧提醒结束均不证明服务正常。

## 身份和时间口径

持久去重键为 `service_id + canonical SHA-256 + days_before`，档位固定为 14、7、1。
指纹规范化为 64 位小写十六进制。不同观测点、重复回报、进程重启、告警配置版本变化及完整数据库恢复共享同一个键；新指纹使用新身份。服务版本不进入去重键，不能靠反复保存重新发送。

按 UTC 时刻计算 `NotAfter - 评估时刻`，不是日历日期或浏览器本地午夜。

| 剩余有效期 | 当前档位 |
| --- | --- |
| 大于 14 × 24 小时 | 未到提醒档 |
| 大于 7 × 24 小时且不超过 14 × 24 小时 | 14 天 |
| 大于 1 × 24 小时且不超过 7 × 24 小时 | 7 天 |
| 大于 0 且不超过 1 × 24 小时 | 1 天 |
| 不大于 0 | 不再生成到期前提醒，结束旧预警 |

首次发现只生成当前最紧急档；更早档位记录为已跳过，不补发。例如剩余 6 天只发 7 天档，14 天档跳过；剩余半天只发 1 天档。在线推进时可分别发出 14 → 7 → 1，进入下一档会结束前一档并取消其未完成任务，防止晚到的旧档提醒。

上述政策不承诺外部渠道绝对只收一条。响应未知时原任务可能重试，渠道不支持幂等时仍可能重复收到；不会另外生成同键的新通知任务。

## 证据与换证

只使用 Store 已接纳、当前服务版本、最近已计划任务中的新鲜结果。较新的待结果任务遮住旧结果。共享 [当前服务摘要](SERVICE_HEALTH.md) 的在线、能力、当前 Gateway 会话、计划/完成时间与未来时间容差判定。

证书须同时满足 Verified=true、合法 SHA-256、非零且有序的有效期、NotBefore 不晚于当前时刻、NotAfter 晚于当前时刻。HTTP 执行器正常验证链、主机名和有效期；没有跳过 TLS 验证的服务/任务配置。默认 Agent 继续使用系统信任库。

同一服务可同时观测多张证书，例如不同边缘节点或 HTTPS 重定向链。取全部当前已知结果中合格证书的并集，逐身份去重。同一指纹出现不同有效期则排除该身份、将证据视为不完整；持久账本已固定的有效期也不能被后续冲突覆盖。

部分观测点缺测时，其他观测点的新鲜、已验证证书仍可产生提醒；这不能证明旧证书已经消失。仅全部当前关联观测点都有新鲜成功结果，且其证书并集不再包含旧身份，才以 `certificate_no_longer_observed` 结束旧预警。未知、忙碌、策略拒绝、离线、不支持、等待结果及 TLS 失败都不能充当换证证明。

提醒规则使用固定的来源观测节点身份；后续相同身份的证据可来自其他当前关联节点。维护仍按该规则来源节点匹配，静默仍按事件匹配。服务或节点关联变更按管理原因结束旧事件，不称为技术恢复。

| 结束原因 | 含义 |
| --- | --- |
| certificate_no_longer_observed | 完整的新鲜成功检查未再观测到旧证书 |
| certificate_threshold_advanced | 已进入更紧急档 |
| certificate_expired | 已达到到期时刻 |
| rule_changed / rule_disabled / rule_deleted | 管理配置或来源变化 |

这些结束均不发送技术恢复消息。事件 API 用 `severity=warning` 标识预警，仍使用已有事件状态和原事件 ID，知悉/静默/维护与尝试查询保持兼容。

## 入队、授权和真实回执

复用 `alert_incidents`、`notification_deliveries`、`delivery_attempts`，不增加第二套发送队列。证书规则不进入主机策略迁移、主机编辑接口或聚合配置。

| 字段或状态 | 可证明的事实 |
| --- | --- |
| queued_once | 至少一次通知意图已和事件、账本事务提交 |
| authorized_once | 至少一次最终发送校验已允许原任务发送 |
| delivered | 原任务获得渠道确认；查看尝试可核对历史 |
| unknown 尝试 | 请求结果不确定，可能已送达 |
| skipped | 此档已经跳过或结束，不补发 |
| history_unavailable | 曾入队，但被引用的投递历史已不可用；不能推定成功 |

发送授权与 `authorized_once` 在同一事务提交。授权不是网络请求开始或收件确认；进程可能在授权后、发送前退出，因此该标记采取保守去重。原任务仍按既有租约、退避、最多五次发送预算和共享渠道等待重试，保留原键、正文、事件地址及尝试序号。

曾授权的同档不另建通知意图，包括后来取消或配置变更的情况。此规则避免重新发送一条可能已经到达外部渠道的消息；不会自动通过新任务重置用尽的重试预算。

旧任务仅在状态为 canceled 且从未取得最终授权时可重新排队，并要求当前档位、配置和新鲜证据仍有效、维护与静默均已解除。未授权的取消不会等待服务故障的重复冷却时间；pending/inflight、失败或历史不可用都不自动另建。维护开始前已发出的请求不可撤回，迟到真实回执保留，不能恢复旧任务的重试权限。

服务版本、服务更新时间 epoch、告警版本、通道、当前来源关联、固定身份和档位在观察提交及发送/回执事务内复核。删除后重新导入同 ID、重置版本不能让旧任务恢复权限。版本失效和档位跨界即使发生在下一轮评估之前，也不能取得旧任务发送权限。

## API、兼容与隐私

`/api/v1/admin/service-monitors/:serviceID/alerting` 增加 `certificate_reminders_enabled`，GET 总是返回布尔值；PUT 显式 true/false 修改，旧客户端省略或 null 保留当前值。服务版本与告警版本冲突返回 409，禁止自动覆盖。

新增 GET `/api/v1/admin/service-monitors/:serviceID/certificate-reminders`，返回 `reminders` 和 `next_before`。倒序 `before` 游标，默认 25、最多 100；拒绝负数、溢出、重复参数。要求管理员登录，no-store；缺失服务返回 404。写配置继续要求 CSRF。

管理员记录只提供指纹、有效期、档位、状态和事件入口，不返回目标 URL、请求/响应正文、断言、队列正文/键、渠道配置或凭据。通知使用服务别名、到期 UTC 时间、档位和短指纹。公开节点接口和 Agent 协议没有新增字段。

```powershell
$env:CGO_ENABLED='0'
go test ./internal/servicehealth ./internal/store ./internal/alerts ./internal/httpapi -run '^Test(Certificate|ServiceAlerting)' -count=1
$env:MYPROBE_TEST_PRIVATE_HTTP='1'
$env:MYPROBE_TEST_HTTP_BROWSER='1'
# PLAYWRIGHT_MODULE 指向已安装的 playwright；浏览器脚本使用本机 Edge。
go test ./internal/agentclient -run '^TestCertificateReminderThroughRealTLSAgent$' -count=1 -v
```

Store 夹具覆盖精确时间边界、两观测点、重复回报、14/7/1 推进、完整备份恢复、模糊结果原任务重试、维护/渠道取消重排、授权后不重建、发送前跨档/过期/配置/epoch 变化、原子回滚、指纹冲突、迁移失败回滚与旧设置默认关闭。

真实链路运行 Agent、生产 HTTP 执行器、调度器、Gateway、评估器、通知工作线程与本地接收端。动态选择私有测试接口，显式允许 CIDR/端口，以生成的 CA 验证 IP SAN 证书；测试专用构造器克隆信任库，未替换拨号或关闭 TLS 校验。叶证书 6 天 → 同地址新指纹 12 小时，实际收到两条提醒、保留两条送达回执、旧预警结束、再次周期检查无新增任务；不是等待真实 14 天的运行验收。

浏览器使用实际提醒链接验证未登录不读事件、登录回预警、独立开关保存刷新、记录及原事件入口，检查明暗主题 360/768/1440 px。既有 HTTP 故障恢复、健康摘要、策略、知悉、静默、维护、聚合和渠道等待流程继续回归。该证据来自本地接收端，不替代公网服务商账号或客户端展示验收。
