# 大库加密备份与恢复容量（SYS-02）

这是定时备份的独立容量验收，不是新的归档格式，也不代表完整 M5、异机恢复或生产切换完成。
生产实现继续使用现有 1 MiB 分块 AES-GCM、独立口令、SQLite 一致快照、验证后原子发布，
已有 `.mpb` 格式不变。实现参考 [定时备份](SCHEDULED_BACKUPS.md)。

## 实际验证的链路

`TestEncryptedBackupCapacity` 默认跳过，显式启用后串行测试 256 / 1024 MiB 两档。
每档使用新的私有临时目录和真实 schema；子进程须持有父进程生成的归属随机值，造数
拒绝已有数据库。输出须为预先存在且可写的绝对目录，不能用文件名代替。先检查剩余
空间，最多三档，每档 32—4096 MiB；较大参数需要相应临时空间。

数据来自经过生产 `SaveReport` 的合法合成 Report，64 个合成网卡的 JSON 小于协议消息
上限，再按 500 行有界 SQL 批次扩展。行内/列内采集时间一致，不用额外填充 BLOB、
稀疏文件或已删除空闲页冒充有效大库。真实创建管理员、Agent 令牌、加密渠道、HTTP
服务及一条实际服务告警导入回执。

造数、生成、恢复各运行在全新子进程，避免把造数内存误认为归档常驻成本。生成调用
生产 `Repository.Generate`：一致性快照 → 加密 → 同步 → 解密验证 → 两份 plaintext 的
流式 SHA256 比较及 SQLite 检查 → 归属签名/无覆盖发布。随后原库新增一个节点，恢复
必须只看到冻结时的旧节点，不能读到备份后的修改。

恢复先分别使用错误备份口令、正确口令但错误应用密钥；均拒绝且不将元数据提升为
“已验证可恢复”。正确恢复调用生产 `VerifyRecovery`，打开隔离还原库，检查全部外键、
管理员/节点/报告/渠道计数、实际 Agent 令牌认证、通知凭据解密、逐行报告 SHA256、
永久回执原始内容摘要，以及原导入请求仍可幂等回放。完整通过才保存 recovery_verified。
含合成令牌的控制文件只在私有 t.TempDir，不进入日志或上传证据。

## 采样与解释

父进程每 50 ms 读取子进程 RSS，另统计案例目录文件大小之和，记录最大采样间隔、
样本数和读取错误。采样可能漏过瞬时峰值；文件总数包括硬链接目录项的重复逻辑大小，
不是物理分配块，不能称为准确的设备写放大或瞬时磁盘峰值。无观测不能写成零。
生成/恢复阶段采样 RSS 必须低于 700 MiB，1 GiB 案例能揭示整库读入内存的回归。
CPU 时间取子进程退出统计，阶段耗时含启动；恢复时间还包含两次拒绝测试。

结果记录 OS/Go、CPU 型号、可见内存、逻辑 CPU、文件系统、剩余空间、源码 hash 和
外部负载说明。新进程不代表设备页缓存冷启动；不清宿主缓存或改系统内存/电源设置。
已有配置预检仍要求约三份数据库大小加 64 MiB 的额外空间；原库、WAL、其他运行数据
还须计入，不能把归档大小当成全部成本。

## 复现

```powershell
$env:CGO_ENABLED='0'
$env:MYPROBE_TEST_BACKUP_CAPACITY='1'
$env:MYPROBE_TEST_BACKUP_CAPACITY_MIB='256,1024'
$env:MYPROBE_TEST_BACKUP_CAPACITY_OUTPUT='D:/isolated-results/backup-capacity'
# 先创建上面的独立输出目录，再执行。
go test ./internal/backup -run '^TestEncryptedBackupCapacity$' -timeout 15m -count=1 -v
```

只上传聚合 JSON，不上传临时库、归档、口令材料或控制文件；结束后由框架清理。
Linux 使用同样环境变量。CI 的 `encrypted-backup-capacity` 独立 job 运行完整两档，
绑定 PR 准确 head 并保存七天聚合证据，不用父提交检查代替当前 head。

## 当前边界

这是静止单节点大库，不是在线写入/每日备份并行或受限 2 vCPU/2 GiB Server 完整容量。
恢复全部合成报告与身份/永久回执，不代表所有永久账本均达到最大容量。同主机还原
不是异机加密恢复、实际外部 Provider/OAuth 或生产 failover。全路线和冻结百节点
24 小时测试保持独立验收。

Windows / Go 1.26.5、i5-13490F、16 逻辑 CPU、可见内存 34,138,931,200 B、
KIOXIA EXCERIA PLUS G3 NVMe、NTFS。gopsutil 的 Fstype 在此机为空，NTFS 由
Get-Volume 独立确认。物理主机同时运行另一份 WSL 百节点测试及部分全仓 Go 测试，
不是空闲独占机器，也未对这些子进程施加 2 CPU/2 GiB 限制。
