# 手动数据库备份与恢复的处理期限

手动完整备份包含一致性快照、加密和下载；恢复包括上传、解密、数据库校验和原子暂存。
这些操作在低CPU配额或较慢存储下可能超过普通HTTP请求的15秒读取、30秒写入限制。
此前633afa8的一次隔离旧站副本演练在约539MB加密归档上传后断开：待恢复文件已经落盘，
客户端却没收到202确认。这次原失败仍保留，不将存在暂存文件视为完整恢复通过。

## 当前行为

- 通过管理员会话和CSRF检查后，备份导出的写入期限为本次操作开始后最多15分钟。
  导出JSON请求仍有原16KiB正文限制和普通读取期限。
- 恢复上传、解密、校验、暂存及202确认共用最多15分钟的绝对处理期限；读取和写入
  socket期限同步延长。原2GiB总上传限制、multipart临时文件处理和原子暂存语义不变。
- 更短的上层请求context期限优先。加密/解密读取也检查请求取消和处理期限，避免请求
  已取消后继续读完整个归档；不会清除或无限延长socket期限。
- 未登录、CSRF失败、配置导入、健康检查及其他接口沿用原行为。普通请求期限及
  下一次keep-alive请求仍由原net/http Server管理。没有新增环境变量、公开API或迁移。

反向代理、客户端和负载均衡器有各自的上传、读取、写入期限。应用的15分钟预算不会
自动修改这些配置；大归档传输需要部署方给相应管理路径留出足够时间。请求头仍须
满足普通读取期限，增大处理预算不能保证任意网络、磁盘或大小的操作都成功。

若连接中断，暂存状态可能已经改变；先按备份/恢复规程核对待恢复状态，保留现场，
不要盲目重复上传或把连接错误当作“尚未执行”。完整恢复仍须重启、重新登录、核对
节点和历史，并用原Agent凭据确认新报告；恢复失败不能仅靠文件存在宣布通过。

## 回归与验收范围

`TestMaintenanceTransfersOutliveOrdinaryHTTPDeadlines`使用小型真实加密数据库和HTTP
连接，将普通socket期限缩短至100ms，以200ms延迟复现三条路径：慢备份响应、
恢复已暂存但确认丢失、慢恢复正文上传。修复前均失败，其中已暂存案例明确记录
pending文件已存在；修复后须拿到完整备份或202/staged/restart_required。

`TestMaintenanceDeadlineScopeAuthorizationAndParentBudget`核对匿名和缺失CSRF请求
不能延长期限、普通管理员读取不受影响、有限的15分钟预算、更短父期限优先，以及
socket期限设置失败时拒绝进入操作且不回显底层诊断。既有维护端点、权限和取消
诊断回归继续执行。

这些小型用例证明期限回归，不代替真实大文件往返、最低硬件、生产切换、真实
GitHub/Telegram或20节点连续24小时。SG上的633afa8原轮证据继续按原源记录；
新修复候选不能仅凭相近源码继承其容量结论。正式站点仍须所有者明确批准后切换。
