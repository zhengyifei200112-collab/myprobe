# 网络质量执行台账与统计契约（NET-01 / NET-02）

状态：计划配置生命周期基础已实现；调度/结果台账、统计和页面仍在开发。本文件落实后续开发文档第 7 节，
不能据此声明覆盖率、长期分位数或多节点比较已经可用。

## 当前证据与问题

`internal/scheduler/scheduler.go` 只在内存保存下次派发时间，节点离线时每轮重试，
重启后重新开始；`Gateway.pending` 也是内存状态。`latency_samples` 保存结果而不保存
任务 ID，旧汇总只有计数和延迟总和。因此已有成功率不能用于推算计划次数、缺测、
真实 ICMP 丢包、P95 或跨桶抖动。

当前 `ListTargetAssignments` 按启用目标和直接分配关系调度，不按节点 `latency_mode`
过滤。该字段是现有显示选择，新增统计不得借机改变已有任务分配语义。
目标组最终也写入 `node_targets`，计划生命周期必须覆盖直接分配、目标组和导入路径。

## 计划与生命周期

1. 为节点/目标保存持久计划 epoch，冻结 kind、host、port、interval、timeout、开始/结束时间。
   同一节点/目标最多一个活动 epoch。只有实际执行定义改变、启停或分配改变才开关 epoch；
   改名称、顺序、公开/隐藏和展示选择不重新排期。
2. 新增前向迁移 042，在同一配置写事务内维护 epoch，覆盖 `node_targets` 及目标定义变更。
   初次迁移只从当前配置建立已知边界，不回填旧计划。配置开始在下一整数秒生效，
   时间区间统一为 UTC 的 `[start,end)`；同秒多次修改允许空 epoch，但不得重叠或重复计数。
   时钟后退时新边界不早于本对计划已保存的边界。
3. 每个 epoch 使用固定 anchor 和 interval 推导计划槽，重启保持原 phase。
   Server 停机期间的计划由区间算术获得，不重放积压探测，也不创建无界缺测行。
   只派发当前仍处于有效派发窗口的槽，过期槽在统计中表现为缺测。
4. 实际尝试使用持久任务行，唯一键 `(epoch_id,scheduled_at)`，任务 ID 全局唯一。
   创建任务后才能向 Agent 发送；派发状态、离线、执行忙、发送失败与收到结果分别保留。
   领取使用有期限的租约；故障恢复不凭内存计数重建计划或重复创建同一槽。
5. 按任务绑定的节点、目标、kind、epoch 和期限验证结果。结果状态与原始延迟样本在同一
   事务提交，成功提交后才 ACK；同任务相同结果重放不重复落样本，冲突结果明确拒绝。
   存储失败不能先消耗唯一有效任务。迟到、过期、配置已替换、删除和重启均有专门测试。
6. 原 v1 Task/LatencyResult 字段已经有任务 ID，基础台账不要求旧 Agent 升级。
   已发布 Agent 实测兼容仍是门槛。地址族、已发/已收包数等新证据采用显式 v2 能力，
   不能给 v1 添未协商字段，也不能把旧记录默认补成 IPv4 或“一包已发”。

计划 epoch 的内部目标地址只用于有权限的执行与诊断。公开查询仅返回允许公开的节点和
目标别名，任务 ID、地址、端口、详细错误和管理备注均不直接公开。

## 统计口径

时间范围使用 `[start,end)`。只把已经过结果接收期限的计划槽放入最终统计分母，
未成熟槽数量单列；界面同时解释请求范围、统计截止和已知计划起点。

| 字段/指标 | 定义 |
| --- | --- |
| 计划数 | 已知 epoch 内已经成熟的槽数，包含 Server 停机期间 |
| 执行成功/失败 | 有可信结果且实际进入探测的成功/失败数；DNS 等失败分类保留 |
| 未执行 | busy、unsupported、invalid_task，以及有证据的派发离线/拒绝等，按原因计数 |
| 缺测 | 已成熟但没有可信执行结果的槽；不得算成探测失败或成功 |
| 覆盖率 | `(执行成功+执行失败)/成熟计划数`，零分母为 null |
| 失败率 | `执行失败/(执行成功+执行失败)`，零分母为 null |
| P50/P95 | 成功 RTT 的 nearest-rank 分位数，返回成功样本数及精度/来源 |
| 抖动 | 同一 epoch、同目标、计划相邻且均成功的 RTT 绝对差之和/配对数；否则断开序列 |
| ICMP 丢包 | 仅有可信 sent/received 证据时计算；工具缺失、DNS 失败和缺测不进入包分母 |

未执行原因是缺测的可解释子分类，不能再次相加到总缺测数，必须满足
`成熟计划数 = 执行成功 + 执行失败 + 缺测`。收到但过期/冲突的结果另作管理诊断，
不能扩大分母。旧历史没有 epoch 时计划数/覆盖率不可用，绝不从当前 interval 反推。

## 分布、抖动与保留

原始范围可用全部成功样本计算精确分位数。跨桶采用可合并的 `histogram_v1`：
先按微秒向上量化，保留八个有效二进制位，以非空 bin 的下界和计数稀疏编码；
零单独编码，最大 RTT 仍为协议规定的 60000 ms。返回 quantile 的上下界和版本。
设计误差预算为 1 微秒量化加不超过 1% 的相对区间宽度，必须用边界及分布测试证明；
合并只加计数，禁止平均各桶 P95。编码版本、计数溢出、非法 bin、非有限 RTT 和损坏数据
均需拒绝；编码必须限制 bin 数和字节数，不能让输入分布造成无界分配。

汇总同时保存成功 RTT count/sum/min/max、计划/执行分类计数、抖动差值和/配对数，
以及首尾槽、首尾成功状态和 RTT。只有相同 epoch 的相邻槽才补跨桶抖动配对。
不同 epoch、失败、未执行、缺测都断开序列。

旧 rollup 没有分布或序列边界，不伪造回填；混合旧数据时明确返回不支持的字段及原因，
不能仅取新部分样本却把结果标为完整一年。新台账和汇总与现有通用历史接口分开演进。
采用既有 7/30/365 天的层级边界，清理分批提交；原始转汇总与原始删除同事务、保持幂等。
关闭 epoch 仅在全部相关记录过保留期后清理。完整备份/恢复必须保留已知计划起点和边界。
显式删除节点或目标沿用现有级联删除其历史的语义；保留期规则适用于仍保留的对象。

## API、页面与完成门槛

NET-02 使用独立质量查询契约，一次请求最多八节点，统一目标、范围、粒度和时区；
返回 raw/histogram/legacy-unavailable 来源和样本数。公开、分享与管理入口各自校验权限，
不可因批量节点查询跨越隐藏节点或分享组范围。图表缺测留空，区分失败区段与低覆盖率。

依次完成：

1. epoch/任务迁移及配置事务生命周期；历史时间边界、同秒编辑、目标组/导入、删除与恢复。
2. Scheduler/Gateway 接入；租约/唯一槽/重启/并发/写入失败/重复/冲突/迟到，以及已发布 Agent。
3. 原始统计和 histogram/jitter 合并；人工固定样本、非等权桶、失败/缺测跨桶、量化边界、
   极端分布误差和实际编码成本测量；旧层明确不可用。
4. 有界保留追赶和真实备份还原；并发写入、失败回滚、容量及历史跨层验证。
5. API 与最多八节点页面；真实后端、明暗主题和 360/768/1440 px；IPv6 不可用、时区/跨天、
   零分母与请求数量均验证。协议新证据缺失时准确显示能力限制。

仅完成数据结构、函数测试或设计文档均不满足 NET-01/NET-02 的完整交付条件。

## 当前实现与验证

迁移 042 保存全局已知计划起点和每个有效分配的 epoch；配置钩子在直接分配、目标定义
及目标组展开的写事务内维护区间。目标组成员及节点分配的展开操作改为同一事务，
避免计划写入失败时只保存了组成员、没有生效分配的部分状态。快照中的目标地址仅在私有
数据库及完整备份中保存，现有公开 API、Agent 消息和诊断导出均没有新增字段。

回归覆盖改名/排序/隐藏/展示选择、频率/地址/端口/kind/超时改变、停用重启、取消分配、
同秒边界、时钟回退、目标组双向展开失败回滚、升级失败原子回滚，以及一致快照恢复后
保留原 epoch ID、phase 和已知起点。旧库只从升级边界开始记录，不把旧样本附到新计划。

下一步接入持久任务与调度器/Gateway；当前接口仍沿用原调度，因此不能把已有历史
成功率描述为覆盖率，也不能声称执行/缺测、分位数和抖动已经交付。
